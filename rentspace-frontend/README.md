# RentSpace — Sprint 3

Flutter frontend สำหรับผู้เช่า เจ้าของพื้นที่ และ Admin ใช้ข้อมูลจำลองร่วมกันในหน่วยความจำ ยังไม่เชื่อม backend และไม่มีการโอนเงินจริง

ปรับจาก ZIP ต้นฉบับโดยแยก Models / Controllers / Store / UI และเชื่อมปุ่มกับข้อมูลใน mock store หน้าจอบางส่วนจัดองค์ประกอบใหม่ แต่คงเมนูตามบทบาท และปรับหน้าตาเป็นธีมขาว-เทา น้ำเงินหม่นแบบ daisyUI พร้อมสลับโหมดสว่าง/มืดได้ในแอป

## เริ่มใช้งาน

ทดสอบด้วย Flutter **3.44.8**, Dart **3.12.2** แนะนำใช้เวอร์ชันเดียวกัน

```powershell
flutter pub get
flutter run -d chrome
```

หากไม่พบคำสั่ง flutter ให้เพิ่มโฟลเดอร์ flutter/bin เข้า PATH หรือเรียก flutter.bat ผ่านพาธเต็ม

```powershell
flutter analyze
flutter test
flutter build web
```

ผล build อยู่ที่ build/web ต้องเปิดผ่าน HTTP server ไม่ใช่ดับเบิลคลิก index.html ZIP นี้ไม่รวม SDK, cache หรือไฟล์ build

Android: `flutter run -d <device-id>` หลังตั้งค่า Android SDK/emulator ส่วน Windows ต้องมี Visual Studio workload Desktop development with C++ ทั้งสองแพลตฟอร์มยังไม่ได้ build ตรวจในงานนี้

## สิ่งที่เพิ่มและแก้ไข

- Models: User, Space, Availability, BlockedPeriod, Booking, PaymentSlip, Issue, AuditEntry พร้อม enum สถานะ
- ใช้ spaceId, ownerId, renterId แทนการใช้ชื่อ ตรวจข้อมูลและสิทธิ์ผ่าน Controllers
- เพิ่ม/แก้ไขพื้นที่ → รอตรวจ → Admin อนุมัติ/ปฏิเสธพร้อมเหตุผล → ผู้เช่าค้นหาเจอ
- เวลาทำการและช่วงปิดแยกตามพื้นที่ บันทึกก่อนมีผล และไม่ทับการจองเดิม
- ค้นหา กรองประเภท รายการโปรด และโปรไฟล์ที่บันทึกในบัญชีจริงของ mock store
- จอง → เจ้าของอนุมัติ → ส่งสลิป → Admin ตรวจ → ยืนยัน → ใช้บริการเสร็จ → บันทึกจ่ายเจ้าของ
- ตรวจเวลาชน เวลาในอดีต เวลาปิด และช่วงเวลาผิดลำดับใน Controller
- JPG/PNG ไม่เกิน 5 MB ตรวจขนาด/ชนิดและ decode ภาพก่อนรับ มี preview/ขยายภาพ
- เก็บหมายเหตุ ประวัติส่งสลิป และเหตุผลไม่ผ่าน ผู้เช่าส่งใหม่ได้
- สลิปไม่ผ่านยังกันเวลาไว้จนกว่าจะยกเลิก และตรวจเวลาชนซ้ำเมื่อส่ง/อนุมัติ
- ปฏิทิน dashboard และรายรับอ่าน Store เดียวกัน ไม่มีตัวเลขรายรับ fallback
- แจ้งปัญหา/ข้อพิพาท → Admin ปิดพร้อมผลแก้ไข → ผู้แจ้งดูผลในโปรไฟล์
- ระงับ/เปิดบัญชี และบันทึกกิจกรรมจากการกระทำจริง
- กำหนดเวลา 24 ชม. สำหรับการตอบรับ/ชำระเงิน ยกเลิกอัตโนมัติเมื่อเลยกำหนด จบรายการอัตโนมัติหลังสิ้นสุด 24 ชม. และจำกัดการจอง 60 นาที–12 ชม.
- Unit tests และ widget tests สำหรับกฎธุรกิจ กรณีผิดปกติ flow เพิ่มพื้นที่/จอง และเมนูทุกบทบาทบนจอ 360/1280

## กฎธุรกิจ

1. เศษชั่วโมงปัดขึ้น เช่น 90 นาทีคิด 2 ชั่วโมง ราคาเก็บเป็น snapshot ใน booking • จองขั้นต่ำ 60 นาที และไม่เกิน 12 ชั่วโมงต่อครั้ง
2. ค่าบริการ 5% หักจากเจ้าของ ปัดเป็นบาท ผู้เช่าไม่มีค่าบริการเพิ่ม
3. คำขอที่ยังดำเนินการรวมสลิปไม่ผ่านกันเวลาไว้ แต่มีกำหนดเวลา: เจ้าของต้องตอบรับภายใน 24 ชม. และผู้เช่าต้องชำระภายใน 24 ชม. หลังอนุมัติ เกินกำหนดระบบยกเลิกอัตโนมัติและคืนช่วงเวลา
4. ผู้เช่ายกเลิกได้เมื่อรอเจ้าของ รอชำระเงิน หรือสลิปไม่ผ่าน โดยระบุเหตุผล
5. รายการรอตรวจสลิป/ยืนยันแล้ว ให้แจ้ง Admin หากยกเลิก ระบบไม่บันทึกการคืนเงิน (การคืนเงินอยู่นอกขอบเขต Sprint นี้)
6. เจ้าของจบรายการได้หลังเวลาสิ้นสุด และ Admin บันทึกจ่ายได้ครั้งเดียว หากเจ้าของไม่กดจบ ระบบจบอัตโนมัติหลังเลยเวลาสิ้นสุด 24 ชม.
7. แก้ไขประกาศจะกลับไปรออนุมัติ การจองและราคาเดิมไม่เปลี่ยน
8. ใช้เวลาท้องถิ่นอุปกรณ์ ควรตั้ง Asia/Bangkok การแปลง UTC สำหรับ backend ยังอยู่นอกขอบเขต

## วิธีเดโม

1. เข้าเจ้าของ → พื้นที่ → เพิ่มพื้นที่ → กรอกข้อมูล → ส่งตรวจสอบ
2. ออกจากระบบ → Admin → ตรวจสอบ → อนุมัติประกาศ
3. ออกจากระบบ → ผู้เช่า → ค้นหาพื้นที่ใหม่ → เลือกวัน/เวลา → ส่งคำขอ
4. เจ้าของ → การจอง → เปิดคำขอ → อนุมัติ
5. ผู้เช่า → การจอง → เปิดรายการ → แนบภาพสลิปตัวอย่าง (ห้ามโอนเงินจริง)
6. Admin → การเงิน → กรองรอตรวจสลิป → เปิดภาพ → ปฏิเสธพร้อมเหตุผลเพื่อทดลองส่งใหม่ หรืออนุมัติ
7. ผู้เช่าดูสถานะ และเจ้าของดูรายการในปฏิทินวันที่เลือก

**รายรับ:** มี seed booking เสร็จสิ้นเมื่อวาน 1 รายการ ราคา 1,100 บาท ค่าบริการ 55 บาท สุทธิ 1,045 บาท เพื่อทดลองโดยไม่ต้องรอ

เจ้าของ → รายรับ จะเห็นพร้อมจ่าย 1,045 บาท จากนั้น Admin → การเงิน → เสร็จสิ้น → RS-DEMO-COMPLETED → บันทึกจ่าย (จำลอง) กลับมาเจ้าของจะเห็นพร้อมจ่าย 0 และจ่ายแล้ว 1,045 บาท

**ทดสอบจุดบอดเดิม:** ปฏิเสธสลิปแล้วใช้ renter2 จองเวลาทับต้องไม่ได้; เปลี่ยนชื่อพื้นที่แล้วเวลาชนยังถูกป้องกัน; เพิ่มช่วงปิดของพื้นที่หนึ่งต้องไม่กระทบอีกพื้นที่; กลับจากหน้าตั้งเวลาโดยไม่บันทึกต้องไม่เปลี่ยนข้อมูล

## ข้อจำกัด

- ข้อมูลอยู่ใน RAM: logout ไม่ล้าง แต่ปิด/รีเฟรชจะเริ่มใหม่ แต่ละแท็บมีข้อมูลของตนเอง ให้สลับบทบาทในแท็บเดียวกัน
- ระบบบัญชี รหัสผ่าน สลิป และการจ่ายเป็น frontend sandbox ไม่มี API/ฐานข้อมูล การยืนยันอีเมล หรือตรวจสลิปอัตโนมัติ
- ไม่มีระบบคืนเงินหรือหักค่าปรับ การคืนเงินและจัดการยอดที่โอนแล้วอยู่นอกระบบ
- ภาพพื้นที่ใช้ URL เดิมจาก Unsplash ต้องใช้อินเทอร์เน็ต โหลดไม่ได้จะแสดงไอคอนแทน
- ยังต้องตรวจ native file picker และ build Android/Windows บนอุปกรณ์เป้าหมาย
- ดูผลตรวจใน VALIDATION.md
