## ลักษณะหน้าจอ

แอปเป็นเลย์เอาต์คอลัมน์เดียวสำหรับมือถือ: top bar ด้านบน + bottom navigation ตามบทบาท (ผู้เช่า 4 เมนู, เจ้าของ 5, Admin 4) และสลับโหมดสว่าง/มืดได้จาก top bar (ค่าเริ่มต้นโหมดสว่าง)

ธีมปรับตามแนวทาง Material 3 Expressive (Google, พ.ค. 2025): การ์ดโค้ง 24px ไม่มีเส้นขอบ ใช้เงานุ่มแทน, ปุ่มแคปซูลสูง 44px, แถบนำทางสูง 68px พร้อม indicator รูปแคปซูล, หัวเรื่องเน้นขึ้น (28px/800) หน้าค้นหามี hero สี tonal พร้อมแถบเลือกหมวดแบบไอคอนพาสเทล ป้ายราคาเป็น tonal pill และหน้าก่อนยืนยันการจองมีกล่องคะแนนรีวิว

บนจอกว้างกว่า 430px แอปจะแสดงเป็นกรอบมือถือขนาด 430px ไว้กลางจอ (เจตนาเพื่อเดโมบนเดสก์ท็อป) — **ยังไม่มีเลย์เอาต์เดสก์ท็อปแบบ sidebar** และ widget tests ที่ความกว้าง 1280 ตรวจว่าไม่เกิด layout exception ภายในกรอบ 430px นั้น

## สิ่งที่ widget tests ตรวจ

login ด้วยข้อมูลว่าง, กรอกฟอร์มเพิ่มพื้นที่แล้วสลับบทบาทให้ Admin อนุมัติ, กดจองผ่าน checkout จนเปิดรายละเอียดสำเร็จ, ตัวกรองงบประมาณ, หน้าก่อนยืนยันการจอง (เงื่อนไข + modal), การจองหลายวัน, เมนูทุกบทบาทที่ความกว้าง 360/1280 โดยตรวจ exception จาก layout และกดปุ่มย้อนกลับ Android แล้วกลับแท็บแรกแทนการออกจากแอป

## การปรับโครงสร้างโลจิก (เพิ่มจากเดิม)

- `platformFee` คำนวณครั้งเดียวตอนสร้าง booking แล้วเก็บเป็น snapshot — เปลี่ยนอัตราค่าบริการภายหลังไม่กระทบรายการเก่า
- `ReasonKind` แยกความหมายของ `Booking.reason` (เจ้าของปฏิเสธ / สลิปไม่ผ่าน / ผู้ใช้ยกเลิก / ระบบหมดเวลา) แทนการใช้ฟิลด์เดียวแบบกำกวม
- `deadlineHint()` บอกเวลาที่เหลือของแต่ละขั้น และแสดงบนการ์ดรายการจองกับหน้ารายละเอียด
- ตารางเปลี่ยนสถานะกลาง `BookingStatusFlow` + `Booking.moveTo()` — ทุกคอนโทรลเลอร์เปลี่ยนสถานะผ่านจุดเดียวที่ตรวจเส้นทางที่อนุญาต
